# InfraLearning LAB

Hands-on learning lab for **Git, Terraform, CI/CD, Ansible and PowerShell**, built from a Windows administrator's point of view.

> **Status:** learning project. Everything here is lab work in a personal test environment, not production experience.

> **Lab vs. production:** everything here is lab work in a personal test environment: one person, broad permissions, one project per exercise, manual steps in places. It is self-directed practice, not production experience. Each lab folder notes where production differs, and [`docs/aws-azure-mapping.md`](./docs/aws-azure-mapping.md) maps the AWS work to the planned Azure phase.

## Goal

Build practical skills in Infrastructure as Code and automation, then apply them to Azure, Entra ID and Intune.

## Lab environment

- Windows 11 with PowerShell 7
- Git for Windows, VS Code
- Terraform
- WSL2 (Ubuntu) for Ansible
- Docker Desktop
- GitHub Actions for pipelines
- AWS CLI and a personal AWS account (region eu-north-1)
- Windows Server and Amazon Linux instances, created and destroyed with Terraform

## What I built

- **Git:** created local workspace, synced with remote repository, tested the most used commands.
- **Terraform:** created local folder, modules, tested and trained with the workflows
- **CI/CD:** learned the core concepts and trained the CI pipelines
- **Ansible:** deployed on local WSL, tested some scenarios
- **PowerShell:** _e.g. scripts working with files, JSON and error handling_
- **AWS:** Terraform-built EC2 instances (Linux and Windows) with locked-down security groups, remote state in S3 with locking, an EBS data volume with snapshots and a restore, and SNS/EventBridge instance alerts
- **Terraform + Ansible:** inventory generated by Terraform, nginx configured on a real instance by a playbook
- **Backup and restore:** CLI and Terraform snapshots, a simulated disaster and restore, and the lifecycle lesson that a backup must not share a lifecycle with its source
